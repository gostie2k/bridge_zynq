

Логика командная. У моста нет «адреса регистра» в кадре — есть команда. Мост
смотрит нулевой байт, понимает по нему, что от него хотят, и уже из этого
знает, сколько байт ждать дальше. Поэтому кадры разной длины:

```
→ FE                      1 байт  — запрос версии моста

→ 20 02 05                3 байта — «запиши внутренний регистр»
     │  └ значение                  Команде 0x20 всегда нужно ровно два
     └─── номер регистра            аргумента: куда и что

→ 02 01 02 80 02 81       6 байт  — «сделай транзакцию на I2C»
     │  │  └──────────┘             Тут аргументов пять, причём первые два
     │  │     данные для шины       говорят, сколько байт в оставшейся части
     │  └ сколько читать
     └─── сколько писать
```

Третий случай нагляднее всего: длина кадра не фиксирована даже для одной и
той же команды. `01 02` означает «писать один байт, читать два», и из этого
мост выводит, что дальше идёт ровно три байта адресов и данных. Напиши мы
`02 02` — за ними пришлось бы отправить четыре байта, и кадр стал бы
семибайтным.

## Сдвиг на байт

Мост отдаёт данные с опозданием **на один байт**: команду он читает к
восьмому такту, и следующий байт уходит на выборку ответа. В даташите этого
нет.


```
FF 53 43 31 38 49 53 36 30 34 20 31 2E 30 2E 33
│  └──────────── "SC18IS604 1.0.3" ─────────────┘
└─ лишний байт
```

## Команды

| Код | Что делает |
|---|---|
| `0x00` | записать в устройство на I2C (не используем) |
| `0x01` | прочитать из устройства |
| `0x02` | записать, повторный старт, прочитать |
| `0x06` | забрать данные из буфера |
| `0x20` | записать внутренний регистр моста |
| `0x21` | прочитать внутренний регистр моста |
| `0xFE` | отдать строку версии |

## Внутренние регистры моста

| Адрес | Что это |
|---|---|
| `0x00` | IOConfig — режимы GPIO |
| `0x01` | IOState — уровни GPIO (туда сведены ALERT от INA226) |
| `0x02` | I2CClock — частота шины, 1,875 МГц / N |
| `0x03` | I2CTO — таймаут шины |
| `0x04` | I2CStat — чем кончилась последняя транзакция |
| `0x05` | I2CAdr — адрес моста как ведомого |

## Коды I2CStat

| Код | Что значит |
|---|---|
| `0xF0` | успешно |
| `0xF1` | адрес не ответил |
| `0xF2` | байт не подтвердили |
| `0xF3` | занят, ещё работает |
| `0xF8` | таймаут шины |
| `0xF9` | неверное число байт |

## Регистры INA226

| Адрес  | Регистр             | Цена разряда      |
| ------ | ------------------- | ----------------- |
| `0x01` | напряжение на шунте | 2,5 мкВ, знаковый |
| `0x02` | напряжение шины     | 1,25 мВ           |
| `0xFF` | Die ID              | всегда `0x2260`   |

```
напряжение, мВ = отсчёт * 5 / 4
ток, мА        = отсчёт / 80      (2,5 мкВ на шунте 0,2 Ом = 12,5 мкА на разряд)
```

## Примеры

`→` что уходит, `←` что в буфере после обмена, `··` мусор.

**Версия.**

```
→ FE

→ 06 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
← ·· ·· 53 43 31 38 49 53 36 30 34 20 31 2E 30 2E 33
        └ с индекса 2
```

**Частота I2C 375 кГц.** Ответа нет, сдвиг не при чём.

```
→ 20 02 05      команда 0x20, регистр 0x02, значение 5
```

1,875 / 5 = 375 кГц — предел моста, впятеро быстрее его состояния по сбросу.

**Таймаут шины.** По сбросу выключен, без него зависшее устройство вешает
мост наглухо.

```
→ 20 03 7F
```

**I2CStat.** Команда два байта, ответ на третьем.

```
→ 21 04 00 00
← ·· ·· ·· F0     успешно
```

**Напряжение с INA226 по адресу 0x40.** Три кадра.

```
→ 02 01 02 80 02 81
   │  │  │  │  │  └ адрес + бит чтения
   │  │  │  │  └─── какой регистр хотим
   │  │  │  └────── адрес + бит записи (0x40 << 1 = 0x80)
   │  │  └───────── читать 2 байта
   │  └──────────── писать 1 байт
   └─────────────── «запиши, перестартуй, прочитай»

→ 21 04 00 00         ждём, пока уйдёт из 0xF3
← ·· ·· ·· F0

→ 06 00 00 00         забираем
← ·· ·· 25 6E         0x256E = 9582 → 9582 * 5 / 4 = 11977 мВд
```


**Ток на 0x47.** Адрес `0x47 << 1 = 0x8E`, регистр шунта `0x01`.

```
→ 02 01 02 8E 01 8F
→ 21 04 00 00
← ·· ·· ·· F0
→ 06 00 00 00
← ·· ·· 24 40      0x2440 = 9280 → 9280 / 80 = 116 мА
```

**Die ID — проверка, что прибор на месте.**

```
→ 02 01 02 80 FF 81
→ 21 04 00 00
← ·· ·· ·· F0
→ 06 00 00 00
← ·· ·· 22 60      0x2260
```
