# SPI ячейки НПУ: инициализация и команды

Два варианта железа, переключаются макросом в `platform_config.h`:

```c
#define NPU_CELL_NEW 1    /* 1 — новая ячейка (вер.2 по КД), 0 — прежняя */
```

Chip select и профиль распиновки ПЛИС из него выводятся и отдельно не
задаются — они привязаны к тому же варианту платы:

| `NPU_CELL_NEW` | `NPU_GPIO_PROFILE` | `NPU_BOARD_CS` | нога CS |
|---|---|---|---|
| 1 — новая | 3 (`0011`) | 1 (`cs1`) | `AB_GPIO3R` |
| 0 — прежняя | 1 (`0001`) | 0 (`cs2`) | `AB_GPIO6R` |

⚠ Для ячейки вер.2 **по КД** нужен профиль `0100`, а не `0011`:

| Нога | по КД = `0100` | `0011` |
|---|---|---|
| `1R` K14 | SCLK | MOSI |
| `2R` N15 | MOSI | SCLK |
| `3R` N16 | MISO | CS1 |
| `4R` L15 | CS1 | MISO |
| `5R` M14 | `CONT_TG` | `tang` |
| `6R` M15 | `tang` | `CONT_TG` |

`0011` — это, по комментарию в `ppos_dsp.v`, «NPU VER2 with power board
from NPU VER1», промежуточный вариант; у него SCLK/MOSI, CS/MISO и обе
тангенты переставлены попарно. Поставить `0100` мешает баг ПЛИС: в
`D_AB_GPIO3R` условие записано как `TYPE == 2'b0100`, литерал
двухбитный, старшие цифры отрезаются, и условие вырождается в
`TYPE == 0`. Третья нога не отпускается под MISO, а выдаётся нулём, и
движок читает собственный ноль — `DEB_DIR` в этом профиле `0x3F`.
Правится на `4'b0100`, после чего `NPU_GPIO_PROFILE` ставить в 4.
CS в `0100` — тоже `npu_ant_cs1`, так что `NPU_BOARD_CS = 1` не меняется.

Профиль решает, какая нога несёт CS, индекс — какой из двух CS движка
опускается. Порознь их держать нельзя: расходясь, они дают ровно одну
картину — SCLK и MOSI идут, CS не опускается, ячейка молчит.

В обоих вариантах это **одна** MAX7301AAX+ на **одном** chip select —
различаются только карты портов. Второй CS не используется нигде: на
новой ячейке CS2 для моста SPI-I2C формируется на самой плате как
`/CS1`, а на прежней вторую микросхему сняли ещё до нас.

Весь код — в `modem.c`, блок `#if NPU_CELL_NEW … #else … #endif`.
API наружу одинаковый в обоих вариантах, `main.c` и `modem.h` от
макроса не зависят:

| Функция | UDP `func_type` |
|---|---|
| `spi_engine_npu_init(&spi_eng_npu)` | — (при старте) |
| `spi_engine_npu_get_status(spi_eng_npu, &status_npu)` | 17 (0x11) |
| `spi_engine_npu_set_ena(spi_eng_npu, panel, ena)` | 18 (0x12) |
| `spi_engine_npu_set_f_diap(spi_eng_npu, diap)` | 19 (0x13) |
| `spi_engine_npu_get_outputs(spi_eng_npu, &npu_out)` | — (раз в секунду) |

Параметры команд 18/19 читаются из `func_par` **побайтно**:
`func_par[0]` — номер панели / код диапазона, `func_par[1]` — `ena`.

Общие параметры контроллера SPI в обоих вариантах:
`SPI_ENGINE_NPU_BASEADDR`, `data_width = 8`, `MODE_0`,
`cs_delay = 100`, `ref_clk_hz = 100 МГц`, `max_speed_hz = 25 МГц`,
рабочая скорость после `spi_engine_set_speed` — **1 МГц**.
Кадр всегда 2 байта: адрес регистра, затем данные.

## Вариант 1 — новая ячейка (`NPU_CELL_NEW 1`)

Одна MAX7301AAX+ (DD9) на **единственном** chip select `NPU_BOARD_CS = 1`
(`cs1`, нога `AB_GPIO3R` в профиле `0011`).
CS2 для моста SPI-I2C формируется на самой ячейке как `/CS1` (инвертор DA2),
контакт 5 разъёма XP3 — `CONT_TG`, а не второй chip select.

### Карта портов

| Порты | Назначение | Направление |
|---|---|---|
| P4, P5 | V1, V2 — преселектор | выход |
| P6–P9 | `1_V_TEMP1..4` — перегрев ПРД №1 | вход |
| P10–P13 | `1_V_POWER1..4` — мощность ПРД №1 | вход |
| P14 | EN1 — питание ПРД №1 | выход |
| P15–P18 | `2_V_TEMP1..4` — перегрев ПРД №2 | вход |
| P19–P22 | `2_V_POWER1..4` — мощность ПРД №2 | вход |
| P23 | EN2 — питание ПРД №2 | выход |
| P24–P27 | EN3–EN6 — питание ПРМ №1–№4 | выход |
| P28 | INT от моста SPI-I2C | вход |
| P29–P31 | RES1–RES3 (контрольные точки X4, X3, X2) | вх / вых / вых |

### Инициализация

Конфигурация портов — два бита на порт:
`00` не использовать, `01` выход, `10` вход, `11` вход с подтяжкой к 1.

| № | Регистр | Данные | Смысл |
|---|---|---|---|
| 1 | `0x00` | `0x00` | No-Op |
| 2 | `0x09` | `0xF5` | P7,P6 вход; P5,P4 выход (V2,V1) |
| 3 | `0x0A` | `0xFF` | P11–P8 вход с подтяжкой |
| 4 | `0x0B` | `0xDF` | P14 выход (EN1), P15,P13,P12 вход |
| 5 | `0x0C` | `0xFF` | P19–P16 вход с подтяжкой |
| 6 | `0x0D` | `0x7F` | P23 выход (EN2), P22–P20 вход |
| 7 | `0x0E` | `0x55` | P27–P24 выход (EN6–EN3) |
| 8 | `0x0F` | `0x5F` | P31,P30 выход; P29,P28 вход |
| 9 | `0x40` | `0x03` | V2=V1=1 — без фильтра (исходное) |
| 10 | `0x2E` | `0x00` | EN1 = 0 |
| 11 | `0x57` | `0x00` | EN2–EN6 = 0, RES2 = 0 |
| 12 | `0x5F` | `0x01` | RES3 = 1 (по протоколу) |
| 13 | `0x04` | `0x01` | выход из shutdown |

Состояния выходов пишутся **до** выхода из shutdown: в shutdown порты
удерживаются входами, значения применяются разом при включении, и
питание панелей не моргает. После каждого кадра `usleep(100)`.

> В протоколе сопряжения шаг 6 записан как `>16'h0B7F` — опечатка:
> регистр `0x0B` задан на шаге 4, конфигурация P23–P20 лежит в `0x0D`.

### Питание панелей — `spi_engine_npu_set_ena`

Одиночный порт = `0x20 + номер порта`. Данные `0x01` включить, `0x00` выключить.

| `com_dev_type` | знач. | Регистр | Порт | Цепь | Панель |
|---|---|---|---|---|---|
| `TX_PANEL_1` | 0 | `0x2E` | P14 | EN1 | ПРД ЕРВА.468714.007 №1 |
| `TX_PANEL_2` | 1 | `0x37` | P23 | EN2 | ПРД ЕРВА.468714.007 №2 |
| `RX_PANEL_1` | 2 | `0x38` | P24 | EN3 | ПРМ ЕРВА.468714.006 №1 |
| `RX_PANEL_2` | 3 | `0x39` | P25 | EN4 | ПРМ ЕРВА.468714.006 №2 |
| `RX_PANEL_3` | 4 | `0x3A` | P26 | EN5 | ПРМ ЕРВА.468714.006 №3 |
| `RX_PANEL_4` | 5 | `0x3B` | P27 | EN6 | ПРМ ЕРВА.468714.006 №4 |

Индекс проверяется на диапазон, при выходе за `RX_PANEL_4` команда
игнорируется.

### Преселектор — `spi_engine_npu_set_f_diap`

Один кадр: регистр `0x40` (группа P4–P7), данные `typ & 0x03`.
`D0 → P4 (V1)`, `D1 → P5 (V2)`; `D2`, `D3` приходятся на P6, P7 —
они входы, запись игнорируется.

| `pow_cntrl_type` | знач. | Данные | V1 (P4) | V2 (P5) | Полоса |
|---|---|---|---|---|---|
| `F_4000_4200_MHz` | 0 | `0x00` | 0 | 0 | 4000–4200 МГц |
| `F_3700_3980_MHz` | 1 | `0x01` | 1 | 0 | 3700–3980 МГц |
| `F_3400_3600_MHz` | 2 | `0x02` | 0 | 1 | 3400–3600 МГц |
| `BYPASS` | 3 | `0x03` | 1 | 1 | без фильтра (исходное) |

Коды перечисления совпадают с `{V2,V1}` таблицы 1 протокола, перекодировка не нужна.

### Контроль индикаторов — `spi_engine_npu_get_status`

| Регистр чтения | Порты | Поле |
|---|---|---|
| `0xC6` (`0x80 \| 0x46`) | P13–P6 | `status_npu.tx_panel_1.word` |
| `0xCF` (`0x80 \| 0x4F`) | P22–P15 | `status_npu.tx_panel_2.word` |

Разряды байта: `D0..D3` — перегрев каналов 1–4, `D4..D7` — мощность
каналов 1–4. Порядок совпадает с полями `struct stat_npu`
(`cntrl_temp1..4`, `cntrl_pow1..4`), перестановка не нужна.

**Чтение двухкадровое.** По даташиту (раздел *Reading Device Registers*,
шаг 6) содержимое регистра приходит вторым байтом **следующего** кадра,
поэтому первым кадром уходит адрес с установленным старшим битом, вторым —
No-Op `0x0000`, и данные берутся из него:

```c
tx_buf[0] = 0x80 | reg; tx_buf[1] = 0x00;
spi_engine_write_and_read(spi_eng, tx_buf, 2);   /* кадр 1: адрес */
usleep(10);
tx_buf[0] = 0x00;       tx_buf[1] = 0x00;
spi_engine_write_and_read(spi_eng, tx_buf, 2);   /* кадр 2: No-Op  */
return tx_buf[1];                                /* данные         */
```

`spi_engine_write_and_read` поднимает и опускает CS на каждый вызов, так
что два кадра — это два отдельных CS-цикла, как и требует даташит.

## Вариант 0 — прежняя ячейка (`NPU_CELL_NEW 0`)

Одна MAX7301AAX+ на единственном chip select `NPU_BOARD_CS = 0`
(`cs2`, нога `AB_GPIO6R` в профиле `0001`), дескриптор — глобальный
`spi_eng_npu` из `main.c`. Это оставшаяся микросхема бывшей com board,
и в рабочей прошивке её CS был именно индексом 0 (`NPU_COM_BOARD_CS`).
Индекс 1 на этой плате опускает `AB_GPIO3R` — CS снятой pow board,
который никуда не идёт.

### Как эта версия получилась

| Версия | Железо | Преселектор |
|---|---|---|
| по КД | две платы с MAX7301, два CS | pow board (CS1), групповая запись `0x40` |
| **рабочая** | pow board снята, одна MAX7301, один CS | порты P26 (`0x3A`) и P28 (`0x3C`) на той же микросхеме |
| новая ячейка | ЕРВА.468349.020 | порты P4/P5 (V1/V2), регистр `0x40` |

Реализована средняя строка. Инициализация снятой микросхемы (10 кадров)
и запись `0x40` на второй CS убраны — они уходили в никуда. Порты P26 и
P28 для этого настроены выходами ещё в прежней инициализации
(`0x0E = 0xD5`, `0x0F = 0x5D`), так что менять конфигурацию не пришлось.

> Вариант по КД с двумя микросхемами, если понадобится, лежит в git:
> `git show b8fa035:modem.c` (`npu_com_board_init`, `npu_pow_board_init`).

### Инициализация

| № | Регистр | Данные | Биты | Смысл |
|---|---|---|---|---|
| 1 | `0x00` | `0x00` | — | No-Op |
| 2 | `0x09` | `0xFF` | 11 11 11 11 | P7–P4 вход с подтяжкой |
| 3 | `0x0A` | `0xFF` | 11 11 11 11 | P11–P8 вход |
| 4 | `0x0B` | `0xFD` | 11 11 11 01 | P12 выход (ПРД №1), P15–P13 вход |
| 5 | `0x0C` | `0xFF` | 11 11 11 11 | P19–P16 вход |
| 6 | `0x0D` | `0x57` | 01 01 01 11 | P23,P22,P21 выход; P20 вход |
| 7 | `0x0E` | `0xD5` | 11 01 01 01 | P26,P25,P24 выход; P27 вход |
| 8 | `0x0F` | `0x5D` | 01 01 11 01 | P31,P30,P28 выход; P29 вход |
| 9 | `0x2C` | `0x00` | — | порт P12 = 0 |
| 10 | `0x04` | `0x01` | — | выход из shutdown |

После каждого кадра `usleep(100)`.

### Питание панелей — `spi_engine_npu_set_ena`

| `com_dev_type` | Регистр | Порт |
|---|---|---|
| `TX_PANEL_1` | `0x2C` | P12 |
| `TX_PANEL_2` | `0x35` | P21 |
| `RX_PANEL_1` | `0x36` | P22 |
| `RX_PANEL_2` | `0x37` | P23 |
| `RX_PANEL_3` | `0x38` | P24 |
| `RX_PANEL_4` | `0x39` | P25 |

Данные — значение `ena` как есть. Проверки диапазона нет: неизвестный
номер просто ни с чем не совпадает и команда ничего не делает.

### Преселектор — `spi_engine_npu_set_f_diap`

Два кадра по одиночным портам:

| Регистр | Порт | Данные |
|---|---|---|
| `0x3A` | P26 | `(typ >> 1) & 1` |
| `0x3C` | P28 | `typ & 1` |

Коды `pow_cntrl_type` те же, что и в новом варианте.

### Контроль индикаторов — `spi_engine_npu_get_status`

| Регистр чтения | Порты | Поле |
|---|---|---|
| `0x44` (уходит как `0xC4`) | P11–P4 | `status_npu.tx_panel_1.word` |
| `0x4D` (уходит как `0xCD`) | P20–P13 | `status_npu.tx_panel_2.word` |

**Чтение двухкадровое**, через общий `max7301_read` этой ветки: старший
бит адреса ставит он сам, поэтому в коде адреса записаны без `0x80`.
Регистры те же, что были.

Раньше здесь стояло однокадровое чтение — данные брались из `tx_buf[1]`
того же кадра, которым ушёл адрес. По даташиту так получается эхо
предыдущей посылки, а не содержимое регистра: MAX7301 разносит адрес и
данные по разным кадрам, и выталкивает данные на MISO только следующий
кадр (No-Op `0x0000`). Именно это кормило индикаторы подрешёток и
«АВАРИЮ».

## Чтение состояния выходов — `0x90 0x18`

Команды 0x16 и 0x17 обратной связи не имеют, поэтому «ПРД1 ВКЛ» в GUI
означало лишь то, что по кнопке щёлкнули. `spi_engine_npu_get_outputs`
читает порты MAX7301 и отдаёт то, что микросхема реально держит.

Читаются **те же одиночные регистры портов** (`0x20` + номер), в которые
пишут `set_ena` и `set_f_diap`. Групповые (`0x40` + номер) дали бы вдвое
меньше кадров, но у них спорная адресация: протокол сопряжения называет
`0x40` группой «P4..P7», а по даташиту `0x40` — это восемь портов начиная
с P0, которых у AAX+ нет. Читать ровно тот регистр, в который писали, —
единственная проверяемая привязка.

| Поле `struct npu_outputs` | Содержимое |
|---|---|
| `ena` | бит на подрешётку, порядок `com_dev_type`: D0 ПРД1, D1 ПРД2, D2–D5 ПРМ1–ПРМ4; 1 — питание подано |
| `f_diap` | код `pow_cntrl_type`, собранный обратно из портов преселектора |
| `cfg` | регистр `0x04` как прочитан: D0 = 1 — ячейка вышла из shutdown |

`cfg` заодно работает признаком живости: единицу в D0 положила
инициализация, и если она читается обратно — значит исправны и SPI, и
микросхема. При `cfg` без D0 функция выходит сразу, не тратя остальные
восемь чтений, а GUI показывает «ячейка не отвечает» вместо нулей:
ноль от неопрошенной ячейки и ноль от снятого питания выглядят одинаково.

Чтение **двухкадровое в обеих ветках**, и с ним же теперь читается
`spi_engine_npu_get_status` прежней ячейки — см. ниже.

### Кэш и темп

Движок SPI один, поэтому читать из обработчика UDP нельзя: обмен влез бы
в середину обмена главного цикла. `get_outputs` вызывается в статусном
цикле `main.c` рядом с `get_status`, результат лежит в глобальном
`npu_out`, а `0x90 0x18` отдаёт кэш немедленно. Состояние выходов меняют
только наши же команды, так что секунды свежести хватает.

Девять регистров по два кадра — восемнадцать кадров, при 1 МГц около
300 мкс раз в секунду. Если ячейки нет, всё обрывается на первом
регистре.

### Ответ

Шесть байт: `[0x90][0x18][ena][f_diap][cfg][резерв]`.

### В PKRVModemControl

Вкладка НПУ, группа «Чтение состояния ячейки»: кнопка «Прочитать» и
галка «Опрашивать раз в секунду». Прочитанное показывается **правой
колонкой рядом с каждой кнопкой питания** и отдельной подписью у
преселектора:

* зелёное — совпало с отправленным;
* красное — расходится, в подсказке что отправляли и что в ячейке;
* прочерк — ответа ещё не было или ячейка не отвечает.

После любой команды НПУ панель сама запрашивает чтение через 1,3 с —
позже обновления кэша в прошивке. Таймер перезапускаемый, поэтому
«Выключить всё» (шесть команд подряд) приводит к одному чтению.

Преселектор сравнивается с последним **применённым** значением, а не с
текущим пунктом списка: список можно покрутить, не нажав «Применить», и
расхождение было бы выдумано.

## Чего в прошивке нет

На новой ячейке на той же шине SPI сидит мост SPI-I2C
**SC18IS604PW** (DD11), за ним восемь **INA226AIDGS** на адресах
I2C `0x40`–`0x47` — поканальный контроль тока и напряжения, их сигналы
`ALERT` сведены на GPIO моста и далее на P28 (INT). Протокол обмена с
мостом и INA226 в документ сопряжения не вошёл. **В прошивке он
реализован с 23.10.2026 — см. `SPI_I2C_BRIDGE.md`**; там же про
отдельный CS моста на `AB_GPIO7R` и разрыв R18.
DOUT микросхемы буферизуется на MISO через
SN74LVC1G125DBV (DD8) с `/OE = CS1`.

Контрольные точки RES1–RES3 (X4, X3, X2) — одиночные площадки, дальше
никуда не идут. Светодиоды VD1/VD2/VD3 висят на `RX_TX`, `CS1`, `CS2`.

## Тангенты

В новом варианте контакт 5 XP3 — `CONT_TG`, тангента (инверсна `RX_TX`).
Раньше на этом контакте был CS2.

Тангент теперь **две, независимые**:

| Линия | Бит creg2 | Setter | Куда идёт |
|---|---|---|---|
| первая | `Tang` (16), `Tang_avt` (17) | `ppos_set_tangenta()` | как и раньше |
| `CONT_TANG` | `NPU_CTX_nCRX` (22), `NPU_CTX_nCRX_avt` (23) | `ppos_set_cont_tang()` | отдельная плата |

Обе можно держать в разных состояниях. Бит `*_avt` отдаёт свою линию
автомату ПЛИС, который дёргает её по тактам слота; само значение бита
тогда не смотрится.

В PKRVModemControl обе выведены на вкладку НПУ: группы «Тангента» и
«Вторая тангента CONT_TANG», у каждой свои ПРМ/ПРД и своё «Авто». На
вкладке Cregs вторая только отображается (`lblContTang`) — панель
получает её через сигнал `contTangChanged`, править оттуда нечего.

### Таблица истинности пары (документ «Логика работы», 20.07.2026)

Линии не независимы: режим задаёт **пара**.

| Состояние | `TX_TG` | `CONT_TG` |
|---|---|---|
| Выход передающего канала на антенну | 1 | 0 |
| Вход приёмного канала с антенны | 0 | 1 |
| Изм. передающего потенциала АР / приёмного канала РН | 0 | 0 |
| Изм. передающего канала РН / приёмного потенциала АР | 1 | 1 |

В штатной работе `CONT_TG` противофазна `TX_TG`; одинаковые значения
уводят тракт на генератор или измерительный прибор вместо антенны.
Поэтому в авто бит 22 должен быть **нулём** (`~tang`). `modem_init()`
ставит `NPU_CTX_nCRX_avt = 1`, бит 22 = 0.

В выложенной версии ПЛИС (`ppos_dsp` `5adecc5`, 30.09.2026, ещё с
двухбитным профилем) первая тангента в профиле `01` сидит на
`AB_GPIO5R` и **не инвертируется**: `M_AB_GPIO5R = tang`. Для
`CONT_TANG` в этой версии мультиплексора ничего нет — профили новой
ячейки (`0011`/`0100`) в репозиторий не выложены.

⚠ Там же видно, что SPI с ячейкой идёт по тем же шести ногам, и две
линии CS движка разведены как `{npu_ant_cs1, npu_ant_cs2} = spi01_cs`:
`cs1` — бит 1 маски, `cs2` — бит 0, то есть `NPU_BOARD_CS = 0` поднимает
именно `cs2`.

Замеры по ILA 16.10.2026 (см. `CONTROL_PLANE.md`) показали, что рабочий
профиль новой ячейки — `0011`, а не `0100`: только у него, как и у
вер.1, четвёртая линия отпущена под MISO, и при этом остался один CS на
`AB_GPIO3R`, а `AB_GPIO6R` прижата в нуль.

В профиле `0001` на `AB_GPIO3R` сидит `npu_ant_cs1` (индекс 1), а CS
прежней ячейки — на `AB_GPIO6R`, то есть `cs2`, индекс 0. В профиле
`0011` остался один CS, и он на `AB_GPIO3R` — значит у новой ячейки
индекс 1. Отсюда таблица в начале документа.

⚠ Сигнал к MAX7301 на плате подписан **CS1** (на нём же светодиод VD2) —
это не `npu_ant_cs1` ПЛИС. На прежней ячейке плата́ной CS1 приходит с
`AB_GPIO6R`, то есть с `npu_ant_cs2`. Путаница этих двух имён и есть та
самая картина «CLK и MOSI приходят, CS всегда в единице».
