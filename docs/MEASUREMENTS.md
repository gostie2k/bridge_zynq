# Измерение MER, RSSI, АРУ и построение созвездия

Документ описывает, как в модеме ПКРВ измеряются качественные показатели приёма
и как они доходят до управляющего ПО. Часть величин считает **модем** (PS-прошивка,
читая AD9361), часть — **хостовое ПО** (Qt, по потоку IQ-отсчётов).

| Параметр   | Где считается              | Источник данных            | Отображение в GUI            |
|------------|----------------------------|----------------------------|------------------------------|
| Созвездие  | ПЛИС захват → отрисовка хост | IQ-поток, UDP :5078        | scatter-график 8-PSK         |
| MER        | хост (Qt)                  | те же IQ-отсчёты           | LCD «MER (dB)», усредн. ×128  |
| RSSI       | модем (AD9361 по SPI)      | `max_pow` из `stat_modem`  | «RSSI (max, dB)»             |
| АРУ        | модем (AGC AD9361)         | `min_gain` из `stat_modem` | «АРУ (min gain)»             |

---

## 1. Созвездие (constellation)

**Что это.** Диаграмма принятых комплексных символов в плоскости I/Q (синфазная и
квадратурная составляющие). Для 8-PSK идеальные символы лежат на окружности через
45° (8 точек); реальные принятые символы образуют «облака» вокруг идеальных — по их
разбросу визуально оценивается качество канала.

**Откуда данные.** Демодулятор в ПЛИС захватывает комплексные отсчёты после АЦП
AD9361. По UDP (порт `5078`) модем шлёт их пачками:

- 256 отсчётов на пакет;
- каждый отсчёт = 4 байта: `int16` I (little-endian) + `int16` Q (little-endian);
- нормировка на хосте: `I_norm = I / 8192`, `Q_norm = Q / 8192` (приведение к ~единичному радиусу).

Поток включается командой `0x90 0x47` (по умолчанию в прошивке выключен, чтобы не
переполнять пул pbuf). Хост рисует последние пачки (трейл из 7 серий) и поверх —
оценённые центры 8 кластеров.

*Реализация хоста:* `constellation_widget.cpp`, `processPacket()`.

## 2. MER (Modulation Error Ratio)

**Определение.** Отношение мощности идеального сигнала к мощности вектора ошибки:

```
MER = 10 * log10( Σ|S_k|² / Σ|S_k − R_k|² )   [дБ]
```

где `R_k` — принятый символ, `S_k` — опорная (идеальная) точка его класса.

**Алгоритм (хост, по приходящим IQ):**

1. Каждый принятый отсчёт `R_k = (I,Q)` относится к одному из 8 секторов 8-PSK по углу
   `φ = atan2(Q, I)` (ширина сектора 45°).
2. По истории (1792 отсчёта) для каждого класса `c` считается **центроид** `S_c` —
   среднее всех попавших в него точек (оценка «идеальной» точки, data-aided).
3. `P_signal = Σ_k |S_{c_k}|²`, `P_noise = Σ_k |R_k − S_{c_k}|²`.
4. `MER = 10·log10( P_signal / P_noise )`.
5. Результат усредняется по скользящему окну из 128 расчётов (по одному на пакет из
   256 отсчётов) — сглаживание показаний.

**Важный нюанс.** Опорные точки `S_c` — это **измеренные центры кластеров**, а не
номинальные точки идеального созвездия. Поэтому метрика отражает прежде всего
**компактность кластеров** (разброс символов) как практический эквивалент EVM.

Связь с EVM: `EVM_rms = 1/√(MER_лин)`, то есть `MER[дБ] ≈ −20·log10(EVM)`.
Чем выше MER — тем «чище» сигнал (выше отношение сигнал/шум на символах).

*Реализация хоста:* `constellation_widget.cpp`, `processPacket()` (расчёт центроидов,
`sig_p`/`noise_p`, усреднение по `kMerWindow = 128`).

## 3. RSSI / мощность принятого сигнала (`pow_rx`)

**Считает модем**, читая регистры AD9361 по SPI на каждый принятый блок
(`main.c`, обработчик RX, ~стр. 2078–2093):

1. Читается регистр RSSI AD9361 → шкала 0.25 дБ/ед.: `rssi = −reg / 4`.
2. Читается текущий индекс усиления АРУ → `rssi = rssi − gain_index`
   (приведение ко входу приёмника: вычитается усиление тракта).
3. Калибровочная поправка: `pow_rx = rssi + 13.94 дБ` (калибровка под тон 3500 МГц).

Итог — **мощность сигнала, приведённая ко входу приёмника, в дБ** (≈ дБм).

За окно ~1 с модем накапливает по принятым блокам `min_pow / max_pow / acc_pow`
(минимум, максимум и сумму для среднего) и раз в секунду отдаёт их в статус-пакете
`stat_modem` (структура `stat_rx`, `modem.h`). Счётчик `cnt_pkt` сбрасывается каждый
кадр.

> В GUI выводится `max_pow` мастера как «RSSI (max, dB)».

---

## 4. АРУ — индекс усиления (`gain_index`)

**Считает модем.** `gain_index` — текущий индекс таблицы усиления, выбранный
**автоматической регулировкой усиления (AGC)** AD9361 (регистр gain, читается тем же
SPI-обменом, что и RSSI). Физический смысл:

- слабый сигнал → AGC поднимает усиление → **большой** индекс;
- сильный сигнал → AGC снижает усиление → **малый** индекс.

То есть индекс АРУ — косвенный индикатор уровня входного сигнала и режима работы
приёмного тракта. За тот же ~1-секундный кадр копятся `min_gain_index / max_gain_index`.

> В GUI выводится `min_gain` мастера как «АРУ (min gain)».

---

## 5. Транспорт статуса

Статус-пакет `stat_modem` (температуры, RSSI, АРУ, счётчики RX/TX) модем шлёт **раз в
секунду** по UDP на адрес/порт, заданные командой `0xA0 group=3`
(`status_ip` / `status_on` / `status_port`). Отправка только при `status_on = 1`.

*Реализация:* `cmd_udp.c`, `send_modem_status()`; вызов раз в секунду из `main.c`.

Управляющее ПО (Qt) держит по сокету на модем: master → host:5007, slave → host:5009;
для созвездия берутся значения **мастера**.
