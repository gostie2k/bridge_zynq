# Конфигурируемый профиль параметров КРТ (план)

Задача: единая структура параметров модема (радио + сеть), которую можно
**сохранять/загружать в XML** (на ПК) и **хранить в QSPI** (на модеме), чтобы
настройка переживала перезагрузку.

## Решения (согласованы)

- **XML — на ПК (Qt).** Модем внутри бинарный. XML-парсера на bare-metal нет.
- **Профиль = агрегат** существующих структур: `device_config` (сеть) + новая
  `radio_params` (радио) + пеленг. Регистровые структуры (`ppos`, `tx_chan0`,
  `rx_chan0`, `pel`) НЕ ломаем — профиль их «накрывает» и умеет применять.
- **QSPI хранит весь профиль** (сеть + радио) одной записью (расширяем `cfg_flash`).
- **Чтение с модема (round-trip) не нужно** — только save/load файла + «Применить».
- **Безопасность старта:** на «чистом» модеме (нет сохранённого профиля) поведение
  ровно как сейчас — дефолты `modem_init()`. Профиль применяется, только если он
  валидно сохранён в QSPI.

## Прошивка

**Новая структура `radio_params`** (`radio_params.h`): tx_freq_khz, rx_freq_khz,
tx_atten_ddb (0.1 дБ), tx_mod, rx_mod, fhss, band (GPIO/УФ), peleng[3].

- `current_radio` — глобал, источник истины по радиопараметрам.
- Команды установки (0x90: 0x02/0x03/0x04/0x06/0x07/0x08/0x15; 0xA0 g4 пеленг)
  дополнительно **записывают значение в `current_radio`** — чтобы было что сохранять.
- **`cfg_flash`** расширяется: запись = header + `device_config` + `radio_params` +
  CRC32 (версия формата 2, A/B-слоты как есть). `0x20` пишет весь профиль, `0x21`
  стирает.
- **Старт:** после `modem_init()` грузим профиль из QSPI; если валиден —
  `radio_params_apply()` перекрывает зашитые дефолты.

**Применение при старте (v1, безопасное подмножество):** tx_freq, rx_freq,
tx_atten, peleng. Поля tx_mod/rx_mod/fhss/band **хранятся и обновляются**, но их
авто-применение при старте включается отдельно (band=GPIO может обесточить УФ —
нужно согласовать семантику).

## ПК (Qt) — следующий этап

- Модель профиля (радио + сеть + телеметрия + пеленг).
- Save/Load XML (`QXmlStreamWriter/Reader`), кнопки «Сохранить/Загрузить профиль».
- «Применить» — последовательная отправка существующих команд.
- Пресеты XML под режимы работы — позже.

## Пример XML (ПК)

```xml
<krt_profile version="1">
  <device role="slave" id="2"/>
  <network ip="192.168.250.21" mask="255.255.255.0" gw="192.168.250.1" peer="192.168.250.10">
    <mac gem="00:0A:35:AA:BB:CC" radio="00:0A:35:DD:EE:03" bridge="00:0A:35:AA:BB:CE"/>
  </network>
  <telemetry ip="192.168.250.22" port="5007" on="1"/>
  <radio tx_freq_khz="3500000" rx_freq_khz="3500000" tx_atten_ddb="100"
         tx_mod="10" rx_mod="10" fhss="0" band="0"/>
  <peleng creg0="0" creg1="0" creg2="0"/>
</krt_profile>
```
